            ملخص الـ API - Service Automation
================================================================
 
Base URL: http://127.0.0.1:5000
Swagger:  http://127.0.0.1:5000/swagger
 
----------------------------------------------------------------
ENDPOINT 1: تنفيذ خدمة
----------------------------------------------------------------
POST /api/execute-service
 
REQUEST:
{
  "ServiceName": "اسم الخدمة",
  "RequestData": { }
}
 
الخدمات والـ RequestData المطلوب:
 
1. طلب فتوى
   RequestData: {"الموضوع": "...", "نص سؤال الفتوي": "..."}
 
2. استعلام عن الرقم التأميني
   RequestData: null
 
3. الاستعلام عن المعاش المنصرف للقائم بالصرف
   RequestData: null
 
4. استعلام عن مخالفات رخص القيادة
   RequestData: {
     "رقم الرخصة": "...",
     "نوع الترخيص": "...",
     "المحافظة": "...",
     "وحدة الترخيص": "..."
   }
 
RESPONSE:
{
  "Success": true/false,
  "Content": "string or null",
  "SubmittedAt": "string or empty"
}
 
نتايج كل خدمة:
 
┌─────────────────────────────────────────┬──────────────┬──────────────┬────────────────────────────────────┬─────────────────────────────┐
│ الخدمة                                  │ Success=true │ Success=false│ Content                            │ SubmittedAt                 │
├─────────────────────────────────────────┼──────────────┼──────────────┼────────────────────────────────────┼─────────────────────────────┤
│ طلب فتوى                                │ اتبعت        │ فشل          │ null دايماً                        │ وقت التقديم بالعربي         │
│ استعلام عن الرقم التأميني               │ الرقم موجود  │ مفيش رقم     │ الرقم التأميني                     │ ""                          │
│ المعاش المنصرف للقائم بالصرف            │ في داتا      │ مفيش داتا    │ اسم صاحب المعاش - صافي المعاش      │ ""                          │
│ استعلام عن مخالفات رخص القيادة          │ الرخصة صح    │ الرخصة غلط   │ رقم اللوحة / عدد المخالفات / الإجمالي│ ""                         │
└─────────────────────────────────────────┴──────────────┴──────────────┴────────────────────────────────────┴─────────────────────────────┘
 
مثال Response ناجح - طلب فتوى:
{
  "Success": true,
  "Content": null,
  "SubmittedAt": "الخميس، 4 يونيو 2026 في 02:51 ص"
}
 
مثال Response ناجح - الرقم التأميني:
{
  "Success": true,
  "Content": "12345678",
  "SubmittedAt": ""
}
 
مثال Response ناجح - مخالفات رخص القيادة:
{
  "Success": true,
  "Content": "رقم اللوحة: 30505190101257 | عدد المخالفات: 0 | إجمالى المخالفات والرسوم القضائية: 0",
  "SubmittedAt": ""
}
 
----------------------------------------------------------------
ENDPOINT 2: تتبع طلب فتوى
----------------------------------------------------------------
POST /api/track-service
 
REQUEST:
{
  "ServiceName": "طلب فتوى",
  "SubmittedAt": "الخميس، 4 يونيو 2026 في 02:51 ص"
}
 
RESPONSE:
{
  "Content": "string or null"
}
 
الحالات:
- الفتوى اتردت عليها  → Content: "السؤال: ... | الإجابة: ..."
- لسه بتتعالج         → Content: null
- الطلب مش موجود      → Content: "الطلب مش موجود"
 
----------------------------------------------------------------
ملاحظات مهمة
----------------------------------------------------------------
1. الـ API بياخد من 60 لـ 180 ثانية لأنه بيشغل أتوميشن على المتصفح
2. الـ HttpClient timeout لازم يبقى 180 ثانية على الأقل:
   _httpClient.Timeout = TimeSpan.FromSeconds(180);
3. الـ SubmittedAt اللي بيرجع من execute هو نفسه اللي هيتبعت في track
4. اسم الخدمة لازم يكون بالظبط زي ما هو مكتوب فوق
